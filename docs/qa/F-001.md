### B1 — [BLOKLAYICI, AC10] Başlık ekranda "MİSSİON CONTROL" yazıyor

**Tekrar üretme:**
1. `npm run build && npm start` (veya `npm run dev`)
2. `http://127.0.0.1:7333/` adresini aç
3. Üst çubuktaki başlığa bak — veya konsolda:
   `document.querySelector('[data-testid="app-title"]').innerText`

**Beklenen:** `MISSION CONTROL` (sözleşme §1: *"uygulama başlığı ('MISSION CONTROL', Departure Mono)"*)
**Gerçek:** `MİSSİON CONTROL`

Ölçülen kod noktaları (prod build üzerinde):
```
M(U+004D) İ(U+0130) S S İ(U+0130) O N   C O N T R O L
```

**Kök neden:** `src/web/index.html:2` `lang="tr"` + `src/web/App.tsx:7` `uppercase` sınıfı.
CSS `text-transform: uppercase` **locale duyarlıdır**; Türkçe'de `i` → `İ` (U+0130) eşlenir.
Kaynak metin `Mission Control` (karışık kâsa) olduğu için iki `i` harfi noktalı büyük İ'ye
dönüşüyor.

**Muhtemel dosya:satır:** `src/web/App.tsx:7-9` (metin + `uppercase`), `src/web/index.html:2` (`lang="tr"`)

**Neden testler yakalamadı (ikinci, daha önemli kusur):** `tests/e2e/shell.spec.ts:25`
`toContainText` DOM metin düğümünü okur, `text-transform`'u **görmez**. Playwright'ın kendi
call log'u (benim koşumdan):
```
locator resolved to <span data-testid="app-title" ... class="... uppercase">Mission Control</span>
Received string: "Mission Control"
```
Yani assert `Mission Control` üzerinde çalışıyor, kullanıcı `MİSSİON CONTROL` görüyor.
`tests/web/App.test.tsx:9` de `renderToStaticMarkup` çıktısına baktığı için aynı şekilde kör
(CSS hiç uygulanmıyor). Bu, sözleşme denetiminin "kanıt ölçtüğünü ölçsün" ilkesinin ihlalidir.

**Önerilen düzeltme:** Başlığı JSX'te birebir `MISSION CONTROL` yaz (CSS dönüşümüne güvenme);
`uppercase` sınıfı marka adı için kaldırılabilir. Ek olarak assert `innerText` üzerinden
yapılsın ki render edilen metni ölçsün — örn. `expect(await title.innerText()).toBe('MISSION CONTROL')`.
(Aynı tuzak Faz 1'de UX dokümanının `uppercase` kullandığı **tüm** kısa etiketler için geçerli:
kanban sütun başlıkları, rozetler. Şimdi çözülmezse tekrarlanır.)

**Kanıt:** `docs/qa/screens/F-001-desktop-1280.png`

### B2 — [BLOKLAYICI, kanıt bütünlüğü] `fsevents` beyaz liste gerekçesi olgusal olarak yanlış

`tests/deps.test.ts:10-16` şunu iddia ediyor:
> *"macOS'ta da prebuilt ikili indirir, node-gyp/derleme gerektirmez"*

**Bu yanlış.** npm registry'den doğruladım (`npm view fsevents@2.3.3 scripts gypfile`):
```
"install": "node-gyp rebuild"
"build":   "node-gyp clean && rm -f fsevents.node && node-gyp rebuild && node-gyp clean"
gypfile:   true
```
`fsevents` **kaynak koddan node-gyp ile derlenen** bir native pakettir (Xcode Command Line
Tools ister). Prebuilt ikili indiren `esbuild`/`playwright` ile aynı kategoride **değildir** —
beyaz listenin varlık nedeni tam olarak bu ayrımdı (sözleşme §3, B1).

Lock'ta doğruladığım gerçek: 5 `fsevents` kaydı da `optional: true, os: ["darwin"], dev: true`
(2.3.2 + 4× 2.3.3). Yani Windows/Linux'ta hiç kurulmaz — developer'ın **bu** kısmı doğru.
Ama macOS'ta kurulur ve **derlenir**; `optional` olduğu için başarısız olsa bile `npm install`
çıkış kodu 0 kalır.

**İkinci kusur — kardeş assert boşta çalışıyor:** `tests/deps.test.ts:36-40`
`lockRaw.includes('node-gyp') === false` iddiasını "native derleme araçları hiç geçmiyor"
başlığıyla sunuyor. `package-lock.json` paketlerin **script'lerini kaydetmez**; bu yüzden
ağaçta node-gyp ile derlenen bir paket (fsevents) dururken bile assert yeşil. Guard, AC2'nin
söz verdiği şeyi ölçmüyor.

**Muhtemel dosya:satır:** `tests/deps.test.ts:9-17` (yanlış gerekçe), `:36-40` (boşta assert)

**Önerilen düzeltme:** (1) Yorumu gerçeğe çevir — "fsevents node-gyp ile derlenir; yalnızca
`optional: true` + `os: ['darwin']` olduğu için Windows/Linux'ta hiç çalışmaz ve macOS'ta
başarısız olsa bile kurulumu bozmaz". (2) Beyaz listeyi çıplak isimle değil, lock'taki
`optional === true && os includes 'darwin'` koşuluyla assert et — fsevents ileride zorunlu
hâle gelirse test kırılsın. (3) `node-gyp` dizge taramasının sınırını yorumda belirt ya da
`gypfile`/`hasInstallScript` üzerinden gerçek bir kontrole çevir.

**AC2 üzerindeki etkisi:** Kullanıcı kararı gereği AC2'nin macOS ayağına KALDI vermiyorum;
ama CEO'nun bilmesi gereken **somut bir tahmin** var: push günü `macos-latest` job'ında
`npm ci` sırasında fsevents için gerçek bir node-gyp derlemesi çalışacaktır. Job muhtemelen
