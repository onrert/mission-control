### 1.3 BLOKLAYICI BBB1 — `process.binding` **modül yüklenirken yakalanırsa** sentinel KÖR (CANLI)

**Tekrar üretme adımları (ürün kodu, hiçbir test dosyası değiştirilmeden):**

1. `src/features/usage/server/usage-aggregator.ts` başına, **modül gövdesinde** (fonksiyon içinde

```ts
const qaProc2 = process as unknown as { binding: (name: string) => QaTcpBinding2 & QaStreamBinding2 }
// MODUL YUKLENIRKEN yakalanir; sentinel testin ICINDE, yani DAHA SONRA kurulur.
```

2. `computeUsageReport` gövdesinden `qaLeakB2Pre()` çağır; fonksiyon içeride

   tek fark referansın nereden geldiği).
3. `npx tsc --noEmit` · `npx eslint <dosya>` · `npx vitest run` · bağımsız dinleyici.

**Beklenen:** ağ çiti KIRMIZI verir (kod yorumu ve `network-capability-guard.test.ts`'in N2b
açıklaması bu vektörde *"asıl savunma sentinel'in runtime kuşatmasıdır"* diyor).
**Gerçek:**

```

npx eslint src/features/usage/server/usage-aggregator.ts → exit 0
npx vitest run tests/features/usage/server → Tests  54 passed (54)      ← İKİ KATMAN DA KÖR

  RAW-DATA "GET /CANLI-B2PRE-yakalanmis-binding HTTP/1.1\r\nHost: 127.0.0.1\r\nConnection: close\r\n\r\n"
  toplam: 111 gerçek TCP bağlantısı + HTTP isteği
```

**Brief'in "pratik mi teorik mi" testi:** gerçek istek çıkıyor ✔ **ve** testler yeşil kalıyor ✔
→ **PRATİK.** Teorik bir bit taşıma değil; ham soket kuruluyor, tam HTTP istek satırı karşı
tarafa teslim ediliyor, tüm takım (1305 test) yeşil.

**Kök neden — ve neden bu, "her monkey-patch böyledir" mazeretine sığmıyor:** sentinel testin
**içinde**, ürün modülü `import` edilip değerlendirildikten **sonra** kuruluyor. Bu yüzden ürün
modülünün gövdesinde alınan her referans **orijinali** tutar. Bu boşluğu sömürebilmek için iki
şart gerekiyor: (a) yeteneğe `import` olmadan erişilebilmesi, (b) yakalanan referansın
`net.connect`'e **düşmemesi**. Bu iki şart bu depoda **yalnızca `process.*` ailesinde** birlikte
sağlanıyor — bunu ölçtüm:

| Aynı "önce yakala" tekniğiyle denenen | Sonuç |
|---|---|
| `const QaWs = globalThis.WebSocket` (modül gövdesinde yakala, sonra `new QaWs(…)`) | **KIRMIZI** — `expected [ 'net.connect' ]`; undici çağrı anında `net.connect`'i **arayarak** kullanıyor, yamalı sürüme düşüyor |
| `net`/`http`/`tls`/`dgram`/`dns` referansını yakalama | **KIRMIZI** — bunlar `import` gerektiriyor, statik AST katmanı beyaz liste (`fs`,`path`) dışı importu zaten yakalıyor |
| `process.binding` / `process.dlopen` referansını yakalama | ✘ **SIZDIRIYOR** — import yok (global) **ve** `net.connect`'e düşmüyor (doğrudan native) |

Yani bu, mekanizmanın genel bir teorik sınırı değil, **tek ve nokta atışı** bir açık.

**Muhtemel dosya:satır:** `tests/features/usage/server/usage-aggregator.test.ts:67-131`
(sentinel test gövdesinde, ürün import'undan sonra kuruluyor) ·
`tests/features/usage/server/network-capability-guard.test.ts:413-431` (N2b'nin
*"asıl savunma runtime sentinel'idir"* iddiası bu biçim için **doğru değil**).

**Kapatmak için gereken minimum — ve KANITLADIM (bu düzeltmeyi kendim koşturdum, ürün koduna
dokunmadan):** `process.binding`/`process.dlopen`'ı, ürün modülü yüklenmeden **önce**
değerlendirilen ayrı bir modülde, **kayıt eden ama fırlatmayan** (orijinale delege eden) bir
sarmalayıcıyla değiştir; test dosyasının **ilk** `import`'u o modül olsun ve ana negatif testte
`expect(qaPreCalls).toEqual([])` de kontrol edilsin (~12 satır):

```ts
// tests/.../network-precapture-sentinel.ts  — test dosyasındaki İLK import
export const qaPreCalls: string[] = []
const p = process as unknown as Record<string, unknown>
for (const key of ['binding', 'dlopen']) {
  const original = p[key] as ((...a: unknown[]) => unknown) | undefined
  if (typeof original !== 'function') continue
  p[key] = function (...a: unknown[]) { qaPreCalls.push('process.' + key); return original.apply(process, a) }
}
```

Ölçüm: bu dosya yerindeyken **yukarıdaki sonda KIRMIZI** (`expected [ 'process.binding', …(23) ]
to deeply equal []`), sonda kaldırıldığında **54/54 yeşil** (yanlış pozitif üretmiyor). ESM
değerlendirme sırası gereği ürün modülü artık **yamalı** referansı yakalar; kaçış yolu kapanır.

## 2. BB1 — sentinel kendi kendini kanıtlıyor mu

### 2.1 `patch()` no-op mutasyonu → **KIRMIZI ✔** (tur 5'te YEŞİL'di)

`patch()` gövdesinin ilk satırına `return` konarak sentinel tamamen devre dışı bırakıldı:

```
× sentinelin öz-testi: kasıtlı net.connect/http.get/WebSocket/process.binding/fetch …
  Tests  1 failed | 53 passed (54)   (+ gerçek 127.0.0.1:80 ECONNREFUSED — sonda gerçekten

```

Tur 5'in M7'si (52/52 yeşil) artık ölü. Aynı şekilde M8 (assert gevşetme) de artık pozitif
kontrolün kendi assert'ini kırar.

### 2.2 `WebSocket` sondası → **KIRMIZI ✔** (tur 5'te 106 istek sızdırıyordu)

Ürün koduna sıradan `new WebSocket('ws://127.0.0.1:45922/…')` (import YOK, gizleme YOK):
`AssertionError: expected [ 'WebSocket' ] to deeply equal []` → 1 failed | 53 passed.
`patch()`'in ok fonksiyonundan `function`'a çevrilmesi doğru düzeltme; `new` ile çağrı da
yakalanıyor.

### 2.3 Pozitif kontrol **anlamlı** — kendine referans vermiyor ✔

Brief'in "beş etiket gerçekten ilgili çağrılardan mı geliyor" sorusu için beş yamayı **tek tek**
kaldırıp yalnızca pozitif kontrolü koşturdum (her seferinde dosya `bak/`'tan geri yazıldı):

| Kaldırılan satır | Pozitif kontrol |
|---|---|
| `patch(globalObj, 'WebSocket', …)` | **KIRMIZI** |
| `patch(processObj, 'binding', …)` | **KIRMIZI** |
| `patch(netObj, 'connect', …)` | **KIRMIZI** |
| `patch(httpObj, 'get', …)` | **KIRMIZI** |
| `patch(globalObj, 'fetch', …)` | **KIRMIZI** |

5/5 etiket **tek tek yük taşıyor**. Test gerçek global giriş noktalarını (`net.connect`,
`http.get`, `new WebSocket`, `process.binding`, `globalThis.fetch`) çağırıyor, sentinel'in kendi
iç nesnelerini değil — no-op mutasyonunda gerçek bir `ECONNREFUSED 127.0.0.1:80` üretmesi de
bunun kanıtı. **Kendi kendine referans YOK.**

### 2.4 ÖNEMLİ (bloklayıcı değil) — pozitif kontrol, **ana negatif iddiayı** korumuyor

Pozitif kontrol mekanizmanın çalıştığını kanıtlıyor ama mekanizma ile **ana testin iddiası**
arasındaki bağı kanıtlamıyor. Tek satırlık bir mutasyon bunu gösteriyor:

```
restore: () => {
  for (const r of restores) r()
  calls.length = 0            // ← QA-TUR6-M9
},
```

Ana test `sentinel.restore()`'u `finally`'de çağırıp **sonra** `expect(sentinel.calls).toEqual([])`
diyor; pozitif kontrol ise assert'ini `restore()`'dan **önce** yapıyor. Sonuç:

```
M9 + §1.1'in (yutulan) process.binding sızıntısı  →  Tests  54 passed (54)
dinleyici: 22 gerçek istek daha (toplam 47)
```

Yani ana negatif iddia **sessizce** boşa düşüyor ve pozitif kontrol bunu görmüyor. Ürün kodu
mutasyonu gerektirmediği için tur 5'in M7/M8'i kadar ağır değil (test dosyasına kasıtlı bir
düzenleme gerekiyor), bu yüzden **bloklayıcı saymıyorum**; ama §1.3 düzeltilirken beraber
kapatılması ucuz: pozitif kontrolün assert'ini `restore()`'dan **sonraya** al, ya da
`restore()`'un `calls`'a dokunmadığını ayrıca iddia et.
